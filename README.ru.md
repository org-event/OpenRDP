# OpenRDP

[English version](README.md)

Открытый RDP-сервер для macOS на [IronRDP](https://github.com/Devolutions/IronRDP). Клиент — любой RDP-клиент с GFX/H.264: Windows App (Mac, Windows, iOS), FreeRDP/Remmina (Linux).

Как устроено:

- захват — ScreenCaptureKit, сразу NV12 full-range BT.709 (цветовое пространство AVC в MS-RDPEGFX), без конвертации;
- кодирование — VideoToolbox H.264, realtime, low-latency, без B-кадров;
- графика — канал EGFX, AVC420 или AVC444. AVC444 — цвет в полном разрешении, как шлют серверы Windows, поэтому текст и цветные края остаются чёткими. По умолчанию его получают клиенты на FreeRDP: их видно по каналу расширенного ввода, который они открывают. Windows App для Mac соглашается на AVC444, а потом рвёт соединение, поэтому получает AVC420. `--avc444` шлёт AVC444 всем, кто его согласовал, `--no-avc444` — никому;
- битрейт — `--bitrate` (20 Мбит/с) задаёт потолок. Если кадры подтверждаются заметно дольше лучшего времени на этом соединении, сервер снижает битрейт на четверть, но не ниже четверти потолка, и медленно поднимает обратно, пока подтверждения быстрые. Частота кадров подстраивается сама: в полёте не больше трёх кадров;
- звук — то, что играет Mac, уходит в клиент по каналу `rdpsnd`: 16-битный PCM на 48 или 44,1 кГц, около 1,5 Мбит/с. Захват через ScreenCaptureKit, с тем же правом «Запись экрана». Сам Mac продолжает играть через свои динамики. `--no-sound` выключает звук; на окне входа его нет;
- шторка — собственные мониторы Мака гаснут, пока подключён клиент, если он об этом попросил. Для этого его альтернативная оболочка должна быть `curtain`: во FreeRDP `/shell:curtain`, в .rdp-файле `alternate shell:s:curtain`, в OpenRDP Client — галочка. Сервер делает гамму мониторов чёрной, и тем, кто сидит рядом, сессию не видно. Захват экрана это не затрагивает. Яркость возвращается, когда клиент отключается или сервер останавливается, даже если он упал. Клавиатура и мышь у Мака продолжают работать: шторка прячет экран, а не блокирует Мак. `--curtain always` или `--curtain never` решают за клиента;
- размер экрана — виртуальный дисплей под окно клиента, HiDPI, предел 3072×1920 по площади (`--max-size`) для клиентов, которые растягивают картинку; клиент, подгоняющий сеанс под окно (FreeRDP с `/dynamic-resolution`), получает запрошенный размер, до 4096 пикселей по стороне — дальше аппаратный кодировщик не берёт; после отключения живёт 5 минут, чтобы окна не разъезжались;
- ввод — `CGEventPost`: скан-коды RDP → keycode Mac, Win → Command, Alt → Option, подсчёт двойных кликов;
- курсор — pointer-сообщения RDP, клиент рисует его сам;
- буфер обмена — текст, картинки и файлы в обе стороны. Файлы, скопированные в Finder, предлагаются клиенту, и он читает их с диска при вставке. Файлы, скопированные на клиенте, скачиваются в `~/Library/Caches/OpenRDP/Clipboard` (хранится только последняя копия) и кладутся в буфер, так что Finder их вставляет. Копию больше 16 ГБ сервер не берёт. FreeRDP на macOS может не вставлять файлы с сервера: ему для этого нужен FUSE;
- питание — Мак не засыпает, пока работает сервер; экран не гаснет, пока подключён клиент; подключение будит уснувший экран.

## Сборка и запуск

```bash
cargo build --release
```

```bash
./target/release/openrdp --user me --pass secret
```

Слушает `0.0.0.0:3389`, вход по NLA. Логин и пароль — собственные для сервера, не учётная запись macOS; пароль можно передать и через `OPENRDP_PASSWORD`. Сертификат самоподписанный (RSA: Windows App не принимает ECDSA), создаётся при первом запуске в `~/Library/Application Support/openrdp`. Остальные флаги — `--help`.

Не открывайте порт 3389 в интернет: на нём круглосуточно перебирают пароли. Снаружи подключайтесь к Маку через VPN (WireGuard, Tailscale); `openrdp-doctor vpn` поднимает туннель WireGuard. Для сервера это обычное подключение.

Права macOS (System Settings → Privacy & Security) выдаются приложению, из которого запущен сервер (Terminal, Ghostty и т. п.), после чего его нужно перезапустить. Сервер сам запрашивает оба права при старте, и macOS добавляет это приложение в списки:

- **Screen & System Audio Recording** — без него картинки нет;
- **Accessibility** — без него не работают клавиатура и мышь.

### Автозапуск

Откройте образ диска из релиза и перетащите OpenRDP в «Программы». Приложение не нотаризовано и остаётся в карантине, поэтому не откроется, пока в Терминале не выполните `xattr -dr com.apple.quarantine /Applications/OpenRDP.app`. Эта команда написана на окне образа. Первый запуск спрашивает имя и пароль RDP, предупреждает про пароль администратора, а затем по очереди проводит через запись экрана и универсальный доступ. Сервер запускается только когда оба разрешения включены.

Из терминала та же установка:

```bash
./target/release/openrdp install --user me --pass secret
```

Эта команда спрашивает пароль администратора через `sudo`.

Копирует сервер в `~/Applications/OpenRDP.app` и ставит LaunchAgent `com.openrdp.server`. Сервер стартует при входе в систему и перезапускается, если упал. Лог пишется в `~/Library/Logs/openrdp.log`. Права macOS в этом режиме выдаются «OpenRDP», а не терминалу. Графическая установка открывает нужные окна сама. Из терминала их по-прежнему нужно включить на самом Маке и перезапустить сервер:

```bash
launchctl kickstart -k gui/$(id -u)/com.openrdp.server
```

Если на диске ещё лежит старая установка, `install` удаляет тот агент, `~/Applications/macRDP.app`, его лог и `~/Library/Application Support/macrdp`. Ничего не переносится, поэтому macOS снова спрашивает Screen Recording и Accessibility.

После обновления сборки снова выполните `install`. Он подписывает приложение локальным сертификатом из отдельной связки ключей в `~/Library/Application Support/openrdp` (`signing.keychain-db`, пароль в `signing.password`), поэтому macOS узнаёт новую сборку как то же приложение, и права сохраняются. Если подписать так не получилось, `install` предупредит и подпишет ad hoc, и тогда права придётся выдавать заново. `openrdp uninstall` удаляет агент, приложение и службу окна входа.

Пока сервер работает, он смотрит на GitHub, не вышел ли релиз новее. Перед установкой показывает диалог; на время замены приложения и перезапуска агента подключение на минуту прерывается. `--update auto` ставит без вопроса, `--update off` проверку выключает. «Позже» спрашивает снова на следующий день.

Тот же `install` ставит LaunchDaemon `com.openrdp.broker` и агент окна входа `com.openrdp.loginwindow` и один раз спрашивает пароль администратора. Пока на Маке окно входа, launchd запускает этот же сервер внутри сессии этого окна. Там он работает от root, как любой агент окна входа; права Screen Recording и Accessibility, уже выданные OpenRDP, действуют и здесь. Картинка — физический дисплей в его текущем размере. Клавиши из RDP-клиента попадают в окно входа, в том числе пароль Mac. После входа этот процесс завершается, сессию забирает LaunchAgent пользователя, клиент подключается заново. Выход из системы возвращает сервер на окно входа.

### RDP-аккаунты

Аккаунты собственные для сервера, не учётные записи macOS, и их может быть несколько: каждый входит под своим именем и паролем и видит тот же рабочий стол, что на экране Мака. Новый вход забирает сессию у открытой. Хранятся в `~/Library/Application Support/openrdp/users` с правами 600; их читает и сервер окна входа. `install --user` добавляет свой аккаунт или меняет ему пароль, остальное — `openrdp user`:

```bash
openrdp user list
openrdp user set sergey        # спросит пароль; или --pass / OPENRDP_PASSWORD
openrdp user rename ivan vanya
openrdp user remove sergey
```

Изменения действуют со следующего подключения, без перезапуска; открытая сессия продолжает работать. Последний аккаунт удалить нельзя. NLA проверяет сам пароль, поэтому он лежит в файле открыто, и защищают его права файла. Старая установка при первом запуске копирует пароль из plist агента в этот файл; следующий `install` убирает его из plist.

Экран FileVault до загрузки macOS по-прежнему недоступен: RDP начинается, когда диск уже открыт и показано окно входа. До этого можно войти через «Общий экран»: `ssh -N -L 5901:127.0.0.1:5900 you@mac`, затем `vnc://127.0.0.1:5901`.

### Проверка и пробуждение: `openrdp-doctor`

[`scripts/openrdp-doctor`](scripts/openrdp-doctor) проверяет всё, от чего зависит удалённый доступ, и чинит частые случаи. Запускать на хосте, например по SSH:

```bash
scripts/openrdp-doctor           # проверка: сессия, агент, порт, права, подпись, питание, сеть
scripts/openrdp-doctor wake      # разбудить экран
scripts/openrdp-doctor restart   # перезапустить агент
scripts/openrdp-doctor vpn       # поднять WireGuard (нужна открытая сессия)
```

С другой машины `openrdp-doctor wol <MAC> [broadcast]` будит уснувший Мак по Wake-on-LAN (на хосте нужен `pmset womp 1`).

`--test-pattern` шлёт синтетическую картинку вместо экрана: проверка видеопути без прав на запись экрана.

Проверка с FreeRDP:

```bash
sdl-freerdp /v:127.0.0.1 /u:me /p:secret /cert:ignore /gfx:avc420
```

В Windows App на Mac клавишу Command стоит отправлять как Windows — тогда на хосте она станет Command.

## Клиент: OpenRDP Client

В [`client/`](client) лежит небольшое приложение для Mac (SwiftUI). Оно подключается к серверам OpenRDP через `sdl-freerdp` из FreeRDP, так что команду FreeRDP не нужно набирать вручную. Полная сборка несёт внутри собственный FreeRDP 3.32.2 с SDL3, FFmpeg (только H.264) и OpenSSL, и на клиентском Маке больше ничего не нужно. Без неё приложение берёт FreeRDP из Homebrew (`brew install freerdp`): `sdl-freerdp` ищется в `/usr/local/bin` (Intel) и `/opt/homebrew/bin` (Apple Silicon), другой путь можно задать в настройках. Если `sdl-freerdp` не найден, приложение сразу об этом пишет.

Для установки скачайте `openrdp-client-<версия>-universal.dmg` со страницы [релизов](https://github.com/org-event/OpenRDP/releases). Приложение работает на Маках с Apple Silicon и Intel, macOS 13 и новее. Перетащите OpenRDP Client в «Программы». Приложение не нотаризовано, поэтому один раз снимите с него карантин:

```bash
xattr -dr com.apple.quarantine "/Applications/OpenRDP Client.app"
```

Каждый прогон CI на пул-реквесте или на `main` тоже оставляет образ диска, в артефакте `openrdp-client-universal`.

- **Список Маков**: имя, адрес, пользователь, параметры. Пароли хранятся в Связке ключей. Все параметры уходят в `sdl-freerdp` через stdin (`/args-from:stdin`), поэтому пароля нет в `ps` и он не пишется в файлы.
- **Подключение в один клик** с `/gfx:avc444 /dynamic-resolution /cert:tofu`, во весь экран или окном заданного размера, с общим буфером обмена. `tofu` запоминает сертификат сервера при первом подключении и не примет его, если он потом сменится. Можно выбрать и «Не проверять» (`/cert:ignore`).
- **Тёмный экран Мака — по желанию.** У каждого сохранённого Мака есть флажок «Гасить экран Мака во время сессии», по умолчанию выключен. Если он включён, приложение передаёт `/shell:curtain`, и сервер OpenRDP гасит свои мониторы, пока клиент подключён. Другие параметры `/shell:` из дополнительных добавляются к нему через запятую.
- **Сочетания FreeRDP без правого Shift.** По умолчанию модификатор сочетаний FreeRDP — правый Shift. Из-за этого заглавные П, К, В, Ь в русской раскладке не набираются, а правый Shift+В отключает сеанс. Приложение пишет `SDL_KeyModMask` в `~/.config/freerdp/sdl-freerdp.json` (или в `$XDG_CONFIG_HOME/freerdp/`, если переменная задана) и показывает сочетания. По умолчанию модификатор — правые ⌘ + ⌥: с ними Enter переключает полный экран, G включает и выключает захват клавиатуры, R разрешает менять размер окна, M сворачивает окно, D отключает сеанс.
- **⌘Пробел и другие системные сочетания доходят до удалённого Мака.** Захват клавиатуры в SDL не даёт клиентскому Маку их перехватить, только если SDL собран с `SDL_MAC_NO_SANDBOX`. Встроенный SDL3 так и собран, а SDL3 из Homebrew — нет. Поэтому для него приложение дополнительно подгружает в `sdl-freerdp` небольшую библиотеку (`DYLD_INSERT_LIBRARIES`, [`client/Keyboard/openrdp_keyboard.m`](client/Keyboard/openrdp_keyboard.m)). Пока FreeRDP держит захват клавиатуры (курсор над окном сеанса) и окно сеанса активно, библиотека отключает системные сочетания клиентского Мака так же, как это сделал бы SDL. Сервер OpenRDP получает ⌘Пробел и переключает раскладку. Ещё библиотека убирает ⌘Q, ⌘W, ⌘H и ⌘M из меню SDL, поэтому эти сочетания уходят на удалённый Мак и не закрывают и не прячут клиент. Это можно выключить в настройках. Чтобы вернуть системные сочетания своему Маку посреди сеанса, нажмите модификатор + G.

Универсальное приложение (arm64 + x86_64) собирается одними Command Line Tools, Xcode не нужен:

```bash
brew install cmake ninja nasm pkgconf
client/build-freerdp.sh  # FreeRDP и его библиотеки под обе архитектуры, один раз (около 20 минут)
client/build.sh --dmg    # client/build/OpenRDP-Client-<версия>.dmg с приложением
```

`client/build-freerdp.sh` скачивает те же исходники, что и Homebrew, и сверяет их SHA-256. Его результат попадает в приложение, только если он есть. `client/build.sh` без него соберёт приложение без FreeRDP, а `--zip` вместо образа диска упакует zip.

Подпись ad hoc. На другом Маке после копирования снимите карантин: `xattr -dr com.apple.quarantine "/Applications/OpenRDP Client.app"`. После каждой новой сборки macOS один раз спросит доступ к сохранённым паролям в Связке ключей: ответьте «Разрешать всегда». Журналы сеансов лежат в `~/Library/Logs/OpenRDP Client/`.
